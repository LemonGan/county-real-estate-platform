# 生产运维手册

本手册适用于灵山房产平台 API。所有涉及凭据、备份文件或生产数据的操作，均不应在聊天、日志或 Git 中输出。

## 每日只读检查

在项目根目录执行：

```sh
/root/miniconda3/bin/python backend/scripts/ops_preflight.py
```

检查项：

- 本机 API 健康接口；
- `/www` 文件系统可用空间；
- `/www/backup` 的总占用。

阈值：

- 可用空间 **≤ 15%**：预警，暂停新增备份任务并检查历史归档；
- 可用空间 **≤ 10%**：严重告警，不执行数据库导出或大文件上传。

可用于监控系统的 JSON 输出：

```sh
/root/miniconda3/bin/python backend/scripts/ops_preflight.py --json
```

## 当前备份策略的确认项

服务器已存在面板管理的定时任务。修改保留策略或删除旧归档前，应先由运营负责人确认：

1. 最少保留天数；
2. 是否已有异地/对象存储副本；
3. 最近一次可恢复性演练日期；
4. 删除范围与可释放容量。

禁止直接以通配符删除 `/www/backup`。优先在面板中调整保留策略，或按已确认的精确日期清理。

## 数据库备份建议

磁盘空间恢复到安全阈值后：

- 每日执行一次数据库逻辑备份；
- 本机仅保留 7–14 天；
- 将加密副本同步至异地存储；
- 每季度进行一次恢复演练到隔离数据库；
- 导出文件不放入网站静态目录，不提交 Git。

## 服务异常处置

1. 运行健康检查；
2. 查看 Supervisor 状态；
3. 检查 API 日志中最近的错误；
4. 先保留证据，再决定重启、回滚或扩容；
5. 涉及数据删除、密钥更换、数据库恢复时必须获得明确授权。

## 当前已启用的项目备份

当前项目已启用独立的 MySQL 逻辑备份：

- 执行时间：每天 02:30；
- 备份目录：`/www/backup/database/buyhouse`；
- 文件权限：归档为 `640`，目录为 `750`；
- 保留策略：仅清理该目录中由脚本生成且超过 14 天的 `buyhouse_mysql_*.sql.gz`；
- 并发保护：使用 `flock`，防止定时任务与人工执行重叠。

首次备份已完成压缩完整性检查，并确认包含数据表定义。仍应在上线前或季度运维中，将备份恢复到隔离数据库进行一次完整恢复演练。

## 隔离恢复演练

2026-07-30 已完成一次隔离恢复演练：最近备份成功恢复出 14 张表，演练结束后自动删除临时数据库。业务数据库未参与恢复操作。

执行方式（将文件路径替换为待验证的备份）：

```sh
cd /www/wwwroot/my_work/buyHouse/backend
/root/miniconda3/bin/python scripts/verify_mysql_backup.py --backup /www/backup/database/buyhouse/<backup-file>.sql.gz
```

脚本只会创建名称以 `buyhouse_restore_check_` 开头的临时数据库；默认在结束时自动清理。除非有明确的人工排障需求，不要使用 `--keep-test-database`。
